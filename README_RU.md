# Hy-MT2 Android — проверка готовой llama-android AAR

Минимальное тестовое приложение для проверки Tencent Hy-MT2-1.8B Q4_K_M на ARM64 Android через готовую AAR `dev.ffmpegkit-maintained:llama-android:0.1.1`.

## Что делает приложение

1. Позволяет выбрать GGUF через системный Android-проводник.
2. Потоково копирует выбранный файл в `Android/data/com.example.hymt2test/files/models/` (без загрузки 1,13 ГБ в RAM).
3. Проверяет сигнатуру `GGUF`.
4. Загружает модель через `Llama.loadModel()` с context=2048, CPU-only, 2–4 потока.
5. Отправляет тестовый/произвольный английский текст в Hy-MT2 и показывает русский перевод, токены/сек и время.

Модель не включена в APK. Скачай официальный файл:

https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF/resolve/main/Hy-MT2-1.8B-Q4_K_M.gguf

Размер около 1,13 ГБ. Для копирования в приватную папку приложения потребуется дополнительное свободное место примерно размером с модель.

## Сборка без Android Studio и локального NDK

В проект включён GitHub Actions workflow `.github/workflows/build-android.yml`.

Workflow использует `android-actions/setup-android@v4` и явно устанавливает только `platform-tools`. Старый пакет SDK `tools` удалён Google, поэтому его нельзя запрашивать через `sdkmanager`; сами Command-line Tools (включая `sdkmanager`) устанавливаются action автоматически.

1. Создай пустой GitHub-репозиторий.
2. Загрузи в него содержимое этого архива (не сам ZIP как один файл).
3. Открой вкладку **Actions** и запусти **Build Android test APK** через **Run workflow**. Сборка также запускается при push в `main`.
4. После успешного выполнения открой запуск workflow и скачай artifact `HyMT2-ReadyAAR-Test-debug`.
5. Установи `app-debug.apk` на ARM64 Android 7+ (на планшете приложение должно устанавливаться на Android 12).

GitHub Actions автоматически загрузит Android SDK платформу/build-tools и Gradle. Android NDK на стороне пользователя не требуется, так как нативный код приходит из предварительно собранной AAR.

## Проверка на планшете

- Нажми «Выбрать GGUF-файл» и выбери `Hy-MT2-1.8B-Q4_K_M.gguf`.
- Дождись копирования.
- Нажми «Загрузить модель в память».
- В поле ввода оставлен пример. Нажми «Перевести на русский».
- Пришли текст результата и строку статуса либо Logcat с ошибкой.

Если загрузка упадёт с ошибкой неизвестной архитектуры/тензора, это означает несовместимость готовой llama.cpp `b9878` AAR с конкретной сборкой GGUF. Тогда следующий шаг — сборка собственной ARM64-библиотеки через GitHub Actions на актуальной ветке llama.cpp.

## Ограничения теста

- Готовая AAR использует CPU/NEON, без Vulkan в бесплатной версии.
- Это диагностический прототип, не интеграция в Tap Translate.
- Q4_K_M — стандартный файл около 1,13 ГБ; экстремальные 1,25-bit / 2-bit модели здесь не тестируются.
- Минимум 2 ГБ свободного места рекомендуется для копии файла и временных данных; фактический расход RAM зависит от контекста и ОС.

## Если GitHub Actions сообщает `Failed to find package 'tools'`

Убедись, что в workflow используется `android-actions/setup-android@v4` и задано `packages: 'platform-tools'`. Не добавляй `tools` в список пакетов. Этот архив уже содержит исправленный workflow.
